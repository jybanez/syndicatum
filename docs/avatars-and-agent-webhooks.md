# Avatar and agent webhook operations

Syndicatum accepts only uploaded JPEG, PNG, and WebP avatars, up to 2 MB and 4096 pixels per dimension. It verifies decoded bytes, re-encodes with GD to strip metadata, stores a randomized non-executable filename outside the web root, and returns a relative application URL. Upload requires a human session and CSRF token; agent assignment additionally requires project owner or administrator access. The media GET endpoint is deliberately unauthenticated because timeline avatars must render broadly within the app. Its 40-hex-character filename is unguessable, responses use the exact verified image content type and `nosniff`, and immutable caching is safe because replacements receive new names. This is profile media, not general file sharing.

Each project agent can have one optional HTTPS webhook in `agent_notification_webhooks`. Its HMAC secret is encrypted and authenticated at rest using the application secret and is returned only when generated or explicitly replaced. URLs with credentials or fragments are rejected. The host is resolved and every IPv4 address must be public unless its exact hostname appears in `SYNDICATUM_WEBHOOK_PRIVATE_HOST_ALLOWLIST`. Delivery resolves again and pins a validated address with cURL `CURLOPT_RESOLVE`, preventing a second DNS lookup from bypassing validation. IPv6-only webhook endpoints are intentionally unsupported in this first implementation.

Committed addressed messages create one durable `agent_webhook_deliveries` row per recipient agent, independent of Realtime. The sender is excluded. The payload contains the canonical message, `occurred_at`, and recipient agent/participant IDs. Workers send `Idempotency-Key` and `X-Syndicatum-Delivery` using the stable delivery UUID, and sign `timestamp + "." + raw_body` in `X-Syndicatum-Signature: sha256=<hex>`. Responses are capped at 64 KiB. HTTP 400–499 responses except 408 and 429 are permanent; transport errors, 408, 429, and 500–599 retry with bounded backoff. A named database worker lock and stale-claim lease recovery prevent overlapping workers from treating lost claims as success. Only a successful recipient delivery sets that addressee's `notified_at`.

Run `php scripts/process-agent-webhooks.php [limit]` from a scheduler. Automatic endpoint disablement, `Retry-After` scheduling, randomized retry jitter, and IPv6 pinning are deliberately deferred; dead deliveries and the configuration's last error remain available for operational inspection.
