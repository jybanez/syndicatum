# Syndicatum v1.0.0-rc.3 — canonical owner-test prerelease

**Status:** Non-production prerelease for isolated owner acceptance. This is not
the stable `v1.0.0` release and is not approved for external, design-partner, or
production traffic. No live deployment or cutover is authorized by this tag.

## Canonical artifact and provenance

The protected annotated-tag workflow must build twice from immutable Git blobs,
byte-compare the outputs, and publish the same canonical producer files:

- `syndicatum-v1.0.0.zip`
- `syndicatum-v1.0.0.manifest.json`
- `syndicatum-v1.0.0.sha256`
- `syndicatum-v1.0.0.provenance.json`

The manifest and provenance identify the exact tagged protected-main commit,
`v1.0.0-rc.3`, content tree, runtime/database contract, and producing workflow.
Verify the published checksum before extraction. The release workflow and its
retained evidence, not a CI-only candidate ref, establish release authority.
If any tagged workflow check fails, issue a new RC; never move or reuse this tag.

## Supported boundary under test

- Fresh Docker installation on MySQL 8.4 only, using baseline
  `syndicatum-mysql84-1.0.0-baseline.1` at schema head `202609180004`.
  Fresh installation must record the published package SHA-256 and tagged source
  commit and must have zero historical migration rows.
- The package includes the reviewed legacy-upgrade plan and exact historical
  migration files for separate source-specific assistance. The forward-only
  adoption path has been rehearsed on an isolated copy of the existing MySQL
  5.7 installation into MySQL 8.4. It preserves the existing user workflow
  while adding the integrated V1 administrator and coordination features;
  lineage and `InstallationState` readiness checks distinguish that upgraded
  history from a fresh baseline install. Their inclusion does not mean the
  running WAMP instance has been upgraded, turn it into a supported prior V1
  release, or authorize an in-place production upgrade.
- Administrator backup creation emits an authenticated encrypted envelope.
  Restore inspection and application are staged against a separate empty
  compatible target; neither operation overwrites the serving database or
  performs automatic cutover. Isolated acceptance included the three exact
  historical avatar assets, verified their hashes in the authenticated
  manifest, and recovered the same assets and database references on restore.
- The reviewed integrated UI, canonical Helper icon assets/notices, and
  webroot `.htaccess` hardening are part of the source contract to be verified
  in the published ZIP.

## Acceptance represented by this candidate

The tagged workflow must rerun the required source, security, portability,
baseline, migration, encrypted-backup, Docker, and canonical-package checks on
the exact tagged revision. It must independently round-trip the exact ZIP
through the ordinary reader and controlled extractor, clean-install that same
ZIP on MySQL 8.4, and download and verify the published files. The separate
isolated test with real historical avatars established encrypted backup and
restore-stage behavior before this release; it was not a live deployment.

## Client and deployment limitations

Codex plugin and browser Companion package identities are separate from the
application tag. Installed-client acceptance for this exact RC is still open;
this note does not certify a wider client compatibility range. The existing
browser Companion v0.10.1 and the locally protected Codex timeline adapter
remain independent packages, not components versioned by this application RC.

Relay-client `api_key` validity remains an owner/owning-system decision and
blocks live deployment, but not creation of this non-production prerelease.
Final owner acceptance, security/release-readiness review, and a separate
live-baseline deployment contract remain open. Production TLS, DNS, proxy,
monitoring, off-host backup retention, and cutover are operator responsibilities.
The exact producing and verifying run IDs will be available in the published
provenance and protected workflow; this tracked note cannot contain its own
commit hash or future run ID.
