# Syndicatum v1.0.0-rc.2 — owner-test release candidate

**Status:** Canonical prerelease for owner acceptance on a fresh isolated
installation. It is not the stable `v1.0.0` release and is not approved for
production traffic.

## Canonical artifact

The protected tag workflow publishes exactly these assets without rebuilding
or mutating the producer output:

- `syndicatum-v1.0.0.zip`
- `syndicatum-v1.0.0.manifest.json`
- `syndicatum-v1.0.0.sha256`
- `syndicatum-v1.0.0.provenance.json`

The manifest records the exact protected-main source commit and this annotated
tag. The provenance must report `canonical: true`. Verify the checksum before
extracting or running the package. See
[`v1-owner-test-handoff.md`](../v1-owner-test-handoff.md) for the short owner
test procedure.

## Supported boundary under test

- Fresh Docker installation only, using the packaged MySQL 8.4 baseline
  `syndicatum-mysql84-1.0.0-baseline.1` at schema head `202609180004`.
- Fresh installation must record the exact package SHA-256 and tagged source
  commit and must contain zero historical migration rows.
- The current internal deployment is not a supported prior V1 release. An
  in-place upgrade from it is outside the V1.0.0 support promise.
- Backup creation uses an authenticated encrypted envelope and the declared
  durable/reset/target-local table policy.
- Restore is stage-only into a separate clean MySQL 8.4 target. It never
  overwrites the serving database, switches traffic, changes DNS or proxy
  configuration, or performs production cutover. A successful result means
  **ready/staged, not live**.

## Acceptance represented by this candidate

The tagged workflow must rerun the complete release-blocking contract,
security, portability, Docker, baseline, migration, canonical-package, backup,
and restore jobs at the tagged revision. It then builds the canonical package
twice from immutable Git blobs, byte-compares the results, round-trips the exact
ZIP through the ordinary reader and controlled extractor, clean-installs that
same ZIP on MySQL 8.4, publishes the original producer files, downloads them,
and verifies their identities again.

The accepted application scope includes the baseline-only installer, Project
API coordination, administrator surfaces, encrypted backup creation, verified
restore inspection, and stage-only restore UI/backend. The Backup / Restore UI
gate closed at source revision `8b86c3ff9aafaf6afea905602b538822edd91739`;
the tag workflow supplies the final protected-main and published-artifact
evidence.

## Known limitations

- This is an owner-test prerelease, not stable production approval.
- Production cutover/orchestration is intentionally not part of V1.
- TLS termination, DNS, reverse proxying, production traffic migration,
  monitoring, high availability, and off-host retention remain operator or
  hosting responsibilities.
- Migration from the current internal pre-V1 deployment is separate,
  source-specific assistance and is not a certified generic import path.
- Stable `v1.0.0` still requires the final owner acceptance and Commercial
  Assessor release-readiness decision for this exact published package.

If this candidate fails any protected release or owner acceptance check,
publish a new `v1.0.0-rc.N`. Never move, replace, or reuse this tag.
