# Syndicatum v1.0.0-rc.1 — release candidate

**Status:** Prerelease candidate for isolated acceptance. Not approved for
external production or stable V1 use. The exact tagged commit, archive SHA-256,
and CI run identity are in the published `release-provenance.txt` asset; verify
that asset and the `.sha256` manifest against the downloaded archive.

## Supported installation boundary under test

- First V1 support path: **fresh Docker installation only**. The current
  internal deployment is not a supported prior commercial release for in-place
  upgrade. Moving its data to a fresh V1 installation is separate migration
  assistance, not a certified upgrade path.
- Candidate runtime: PHP 8.2/Apache on Debian Bookworm, Compose `app`, `db`, and
  `worker`, and MySQL **5.7.44 with strict SQL mode**. The terminal MySQL 5.7
  release is a legacy stabilization baseline, not an upstream security-
  maintenance claim.
- Follow [Docker deployment](https://github.com/jybanez/syndicatum/blob/v1.0.0-rc.1/docs/docker-deployment.md) for setup, secrets,
  migration status, health, backup, restore, and diagnostics. The RC workflow
  must exercise a clean install and backup/restore from the **downloaded
  published archive** before this candidate receives acceptance evidence.

## Schema, configuration, and compatibility

- Provisional candidate migration head on the delivery-diagnostics branch:
  `202609180004_delivery_terminal_timestamps`. Recheck this value against the
  final protected-main commit before tagging. The tagged artifact and
  `migration-status` output are authoritative at release time; released
  migration checksums are immutable.
- Create a new protected `.env` from `.env.example`. Preserve the HMAC and
  master encryption keys with backups; do not publish secret values. See the
  Docker runbook for required variables and credential rotation.
- Coordination contract: the candidate
  [`v1-coordination-contract.md`](https://github.com/jybanez/syndicatum/blob/v1.0.0-rc.1/docs/v1-coordination-contract.md) and
  [cross-provider matrix](https://github.com/jybanez/syndicatum/blob/v1.0.0-rc.1/docs/v1-cross-provider-contract-matrix.md) contained in
  the tagged archive. Their complete V1 freeze and installed-client acceptance
  are **not yet claimed** by these notes.
- Package identities present in the candidate source: Codex plugin
  `0.1.0+codex.20260916171323` and Companion extension `0.10.0`. These are
  source package versions, **not** a claim that those installed versions have
  passed the final cross-provider acceptance matrix. No wider compatible
  client-version range is asserted.

## Open gates and known limitations

- Installed Codex, ChatGPT, Gemini, and remote-MCP client acceptance, including
  negative identity isolation and recovery, remains separate from source and
  Docker-artifact tests.
- Security, third-party legal/license inventory, and production hardening
  review remain open. In particular, do not equate functional MySQL 5.7.44
  acceptance with current upstream security support.
- Delivery-diagnostics source tests and isolated-candidate real-worker recovery
  have been accepted for P0.6. P0.6 remains open until those checks pass from
  the exact published RC archive, with its hash and provenance recorded. This
  source-level evidence is not a production receiver or installed-client test.
- Permission-safe onboarding and the narrow Phase 1 coordination surfaces
  remain on the V1 implementation checklist; this RC does not assert those
  product gates are complete.
- No supported in-place migration or rollback from the existing internal
  pre-V1 deployment is promised. Subsequent supported releases will need
  upgrade and rollback acceptance from the immediately previous supported
  release.

If this RC fails any gate, publish a new `v1.0.0-rc.N` tag and artifact. Never
move or reuse this tag.
